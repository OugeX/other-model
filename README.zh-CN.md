# Other Model 中文说明

![Other Model logo](docs/logo.png)

Other Model 是一个面向 **Codex / GPT 系列工作流** 的本地 OpenAI 兼容网关，核心目标是解决 **单一 API 中转站失效后，vibe coding / 自动化开发工作流直接停摆** 的问题。

你可以把多个 API 中转站同时接入到 Other Model，由它在本地统一对外暴露一个 `/v1` 入口，再根据配置自动执行：

- 多供应商轮询
- 单供应商故障自动切换
- 模型发现与健康检查
- 请求日志与错误定位
- 余额/健康状态查看
- 一键生成 Codex 接入配置

这样 Codex、脚本、IDE 插件、CLI 工具都只需要连接到 **一个本地地址**，而不需要在每次上游站点失效时手工改来改去。

## 这个项目是为了解决什么问题

在实际使用 API 中转站时，最常见的问题不是“完全没有模型”，而是：

- 某个中转站临时挂了
- 某个站点账号被限流、风控或额度耗尽
- 某些模型在 A 站可用、在 B 站不可用
- Codex 正在跑任务时，单一上游突然失效

一旦你把 Codex、CLI、编辑器插件都直接绑死在一个中转站上，上游一出问题，整个工作流就断掉了。

Other Model 的设计思路就是：

1. **把多个 API 中转站统一纳管**
2. **本地暴露一个稳定的 OpenAI 兼容网关**
3. **优先自动轮询，必要时自动切换**
4. **尽量不让上游抖动影响你的持续开发**

## 适合谁用

这个项目尤其适合下面几类用户：

- 同时维护多个 API 中转站账号的人
- 重度依赖 Codex / GPT-5.4 / GPT-5.5 做开发的人
- 不想因为单一供应商异常就中断工作的开发者
- 希望快速切换、测试、比对不同中转站的人
- 需要把本地开发工具统一接到一个稳定入口的人

## 核心能力

### 1. 多供应商统一管理

支持添加、编辑、启用/停用、导入、导出多个供应商配置。

支持的典型场景：

- 同时接多个 newapi / sub2api / 兼容 OpenAI 的中转站
- 一个站点掉线后自动切换到下一个站点
- 保留多个备用供应商，避免单点故障

### 2. 轮询与故障切换

Other Model 会把本地请求转发到上游供应商，并支持：

- 自动轮询
- 固定单供应商
- 401 / 402 / 403 / 429 / 5xx 等情况下自动 failover
- 首包输出前切换，避免流式响应中途重放

这对于持续运行的 Codex / CLI 工作流特别重要。

### 3. Codex 一键接入

项目内置了 Codex 配置辅助能力：

- **桌面版**：可一键写入 `~/.codex/config.toml`，并自动备份
- **Web 版**：可直接复制配置片段，或下载 `configure-codex.sh`

目标是把 Codex 接入 API 中转站的过程尽量收敛为：

1. 配好供应商
2. 点一下 Codex 配置
3. 直接开始用

### 4. 余额查询 / 健康查看

除了传统额度接口，还支持登录型余额查询适配器：

- `quota_api`
- `newapi_login`
- `sub2api_login`

适合那些**没有公开余额接口，但有账号密码登录接口**的供应商。

你可以在“额度”页：

- 单独查询某个供应商余额
- 一键批量查询全部供应商余额
- 查看余额、历史消耗、错误原因

### 5. Web 自托管版本

除了桌面版，项目还提供 **单机自托管 Web 版**：

- 一个 Rust 服务同时提供管理后台、REST API 和 `/v1` 网关
- 适合部署到自己的服务器或常驻机器
- 可通过浏览器管理供应商、查看余额、生成 Codex 配置

## 主要特性一览

- Tauri v2 桌面端（React + TypeScript UI）
- 单机自托管 Web 版本
- 本地 OpenAI 兼容 `/v1` 网关
- GPT-5.4 / GPT-5.5 模型发现与测试
- 供应商导入导出
- 请求日志
- 大请求体支持
- 长连接 / 流式响应支持
- 一键网关自检
- Codex 配置辅助

## 本地网关地址

- 桌面版默认：`http://127.0.0.1:14555/v1`
- Web 版默认：`http://127.0.0.1:14556/v1`

对于 Codex、CLI、脚本、编辑器插件来说，通常只需要连接这个本地地址即可。

## 快速开始

### 开发环境

```bash
npm install
npm run build
npm run tauri -- build
```

Rust 测试：

```bash
cd src-tauri
cargo test
```

### 运行 Web 版

```bash
npm run build
cd src-tauri
cargo run --bin other-model-web -- serve --host 127.0.0.1 --port 14556
```

或者在仓库根目录直接运行：

```bash
npm run web:serve
```

## Web 版环境变量

- `OTHER_MODEL_DB=/path/to/other-model.sqlite`：覆盖 SQLite 数据库路径
- `OTHER_MODEL_ADMIN_PASSWORD=...`：设置或重置管理员密码
- `OTHER_MODEL_WEB_DIST=/path/to/dist`：覆盖前端静态资源目录

## 本地存储说明

当前 MVP 阶段会以**明文**方式保存部分配置：

- API Key
- 供应商导入导出 JSON
- 登录型余额查询所需账号密码

因此请务必把本地数据目录、数据库和导出文件保管好，不要随意外传。

## 项目定位总结

一句话概括：

> **Other Model 是一个给 Codex / API 中转站用户准备的“本地多供应商容灾网关”。**

它不是单纯的“再包一层 UI”，而是把多个中转站统一编排起来，降低单点故障对开发流程的影响，让你的 vibe coding 更连续、更稳定。
